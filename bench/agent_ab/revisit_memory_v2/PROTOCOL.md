# Revisit-memory v2 preregistered protocol

Independent replacement for v1; v1 is neither modified nor regraded. Three held-out Java sequences use distinct declarations, numeric facts, and mutations. Calls are stateless and isolated. CONTROL rereads authoritative source every visit. TMF_MEMORY stores after first visit only a source-bound claim, anchors, freshness, and provenance (never answers, prompts, or transcripts), adopts it only while fresh, misses unknown identities, and blocks stale claims before a localized authoritative reread. Each mutated tree includes one semantic mutation and one unrelated mutation.

The broker must return JSON only with `evidence_source` (`SOURCE|MEMORY|NONE`), `memory_hit` (`HIT|MISS|NOT_APPLICABLE`), task-requested typed fields, and `citations` (`[{path,line}]`). Goldens score only explicitly requested typed fields plus citation path/line coverage and the two enums. Natural-language answer wording is not scored.

Primary metrics: typed-field correctness and citation coverage. Secondary: source lines/bytes, tokens, latency, hit/adoption, stale errors, stale detection and localized-reread precision/recall. Stop gate: freeze protocol/manifest/tasks/goldens/runner/audit/tests and fixtures; run scorer/leakage/budget self-tests; then one-sequence smoke. Run the three-sequence pilot only if every paired smoke arm/phase is schema-valid and correct, leakage/budget checks pass, stale is blocked, and localized reread is exact. No post-result edits to frozen inputs. Support requires no correctness/citation regression, materially lower fresh-revisit reads, localized mutation rereads, and no stale trust errors. Otherwise verdict is not supported/inconclusive.
