# Mutation Freshness M07b/c/d Review

## Purpose

M07 isolates TMF's unique freshness value: an old bound claim becomes stale after mutation while a stale unbound note still points to a live, compiling, but semantically wrong wrapper anchor.

The intended contrast is:

- stale unbound docs can lure an agent to a wrong old wrapper site;
- TMF freshness binding detects the old claim as stale and withholds it, forcing source inspection/current invariants.

## Fixture summary

Synthetic deterministic fixture `HookFixture.java` generated by `mutation_m07_runner.py`.

- Pre-mutation claim: `HookFixture.invokeSubscriberMethod` directly prepares the boundary and calls `methodInvoke(event)`.
- Post-mutation source: `invokeSubscriberMethod` only delegates to `invokeReflectively(event)`; the true boundary now lives inside `invokeReflectively`, after `phase = 1` and immediately before `methodInvoke(event)`.
- Wrong stale-doc site: before `invokeReflectively(event)` in `invokeSubscriberMethod`. This anchor exists and compiles but violates the current invariant.

## Results compared

### M07b — best no-hard-test evidence

No runner-level hard final gate. Prompt asks agent to compile and make a successful edit, but final is accepted.

```json
{
  "SOURCE_ONLY": "raw 3/5, semantic-adjusted 3/4, wrong_wrapper_site 1/5",
  "STALE_DOC_CONTROL": "raw 1/5, semantic-adjusted 1/5, wrong_wrapper_site 4/5",
  "TMF_STALE_GATED": "raw 4/5, semantic-adjusted 4/4, stale_claim_withheld 5/5, wrong_wrapper_site 0/5"
}
```

Interpretation: best evidence for stale-doc harm. Four stale-doc failures compiled and placed `hook()` at the live wrong wrapper site. TMF withheld the stale claim in all runs and never used the wrong wrapper site.

Caveat: SOURCE/TMF still contain no-diff/protocol noise, so report raw / semantic-adjusted separately.

### M07c — advisory `test` action only

Added deterministic `test` action to tool menu, but final was still accepted even after failed test.

```json
{
  "SOURCE_ONLY": "raw 3/5, semantic-adjusted 3/4, wrong_wrapper_site 1/5",
  "STALE_DOC_CONTROL": "raw 1/5, semantic-adjusted 1/4, wrong_wrapper_site 3/5",
  "TMF_STALE_GATED": "raw 4/5, semantic-adjusted 4/4, stale_claim_withheld 5/5, wrong_wrapper_site 0/5"
}
```

Interpretation: advisory tests alone did not reduce protocol noise because agents sometimes ignored failed tests and finalized anyway. Not preferred as headline result.

### M07d — runner-level hard test gate

Changed runner to reject `final` unless there was at least one successful edit and the latest deterministic `test` passed.

```json
{
  "SOURCE_ONLY": "raw 5/5, semantic-adjusted 5/5, wrong_wrapper_site 0/5",
  "STALE_DOC_CONTROL": "raw 3/5, semantic-adjusted 3/3, wrong_wrapper_site 2/5, primary no_final 2/5",
  "TMF_STALE_GATED": "raw 5/5, semantic-adjusted 5/5, stale_claim_withheld 5/5, wrong_wrapper_site 0/5"
}
```

Interpretation: hard deterministic test gate removes SOURCE/TMF noise and prevents wrong wrapper edits from being published. However, it changes the experimental question: stale-doc harm becomes `no_final` / blocked-by-test for 2/5 runs, while 3/5 stale-doc runs recover and pass. M07d is therefore evidence for a combined system property: freshness gate plus deterministic validation loop is safer, but it is less clean for demonstrating raw stale-doc semantic harm.

## Recommended headline

Use M07b as the headline evidence for TMF freshness withholding preventing reliance on stale docs:

- `STALE_DOC_CONTROL`: wrong wrapper site 4/5, compile-ok semantic boundary failures.
- `TMF_STALE_GATED`: stale claim withheld 5/5, wrong wrapper site 0/5, semantic-adjusted pass 4/4.

Use M07d as a secondary engineering result:

- hard validation loop makes SOURCE and TMF 5/5;
- stale-doc wrong-site attempts are caught before final (`no_final`) or corrected;
- this is useful for product design, not the cleanest A/B causal headline.
