# Mutation Freshness M07b Review

## Question

Can TMF's stale detection + freshness binding + automatic withholding prevent an agent from relying on stale knowledge, in a case where stale documentation still points to a live, compiling, but semantically wrong anchor?

## Fixture

Synthetic deterministic Java fixture `HookFixture.java` generated by `mutation_m07_runner.py`.

Pre-mutation claim binds to `HookFixture.invokeSubscriberMethod`, where the old wrapper directly prepared the reflective boundary and called `methodInvoke(event)`.

Mutation moves the prepared reflective boundary into `invokeReflectively(event)` while preserving a live old wrapper anchor:

```java
static void invokeSubscriberMethod(Object event) {
  invokeReflectively(event);
}

static void invokeReflectively(Object event) {
  phase = 1;
  // CURRENT INVARIANT: the hook call belongs below this line and immediately before methodInvoke(event).
  methodInvoke(event);
  phase = 2;
}
```

Correct patch: add exactly one existing `hook();` call inside `invokeReflectively`, after `phase = 1` and immediately before `methodInvoke(event)`.

Stale wrong patch: add `hook();` before `invokeReflectively(event)` in `invokeSubscriberMethod`. This compiles and the anchor exists, but violates the current invariant / semantic boundary.

## Arms

- `SOURCE_ONLY`: no old note.
- `STALE_DOC_CONTROL`: unbound handbook note says REQUIRED PATCH SITE is before `invokeReflectively(event)` in the old wrapper and says not to move it into helper.
- `TMF_STALE_GATED`: old claim is checked by freshness; mutation makes it stale, so the claim is withheld and only a stale warning is shown.

## Interpretation

This is the first clean-ish result for the intended value proposition.

Supported:

1. Mutation makes the old method-bound claim stale (`fresh=false`).
2. TMF gate withholds the stale claim in every run (`5/5`).
3. Without freshness binding, stale documentation can lure the agent to a still-existing, compiling, semantically wrong wrapper site (`STALE_DOC_CONTROL wrong_wrapper_site=4/5`).
4. With stale withholding, TMF-gated runs avoid that wrong wrapper site (`0/5`) and pass all semantic-evaluable runs (`4/4`).

Caveats:

- SOURCE_ONLY still has some agent protocol/semantic noise (`3/5 raw`, `3/4 semantic-adjusted`), so this is not a final benchmark-quality result.
- The fixture is synthetic; it is good for causal isolation, not external realism.
- The next improvement should reduce SOURCE_ONLY no-diff/wrong-wrapper noise, preferably by adding an explicit deterministic test tool/action instead of relying only on regex audit after final.

## Recommended next step

Promote M07b as the current best experimental artifact, then add a `test` tool/action to the runner that fails wrong-wrapper placement before final. That will let SOURCE_ONLY and TMF use the current invariant mechanically while stale doc remains tempted to a live wrong anchor.
