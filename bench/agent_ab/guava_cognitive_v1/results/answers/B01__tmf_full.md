For a non-`DeadEvent` with no matching subscribers, `EventBus.post(Object)` does not call `dispatcher.dispatch` for the original event. The existing `else if (!(event instanceof DeadEvent))` path instead constructs `new DeadEvent(this, event)` and calls `post(...)` again. On that recursive `EventBus.post(Object)` call, any subscriber for `DeadEvent` makes `eventSubscribers.hasNext()` true, so the call proceeds to `dispatcher.dispatch(Object, Iterator<Subscriber>)` for the wrapped event.

Removing the re-post branch removes this entire path: `EventBus.post(Object)` for an unsubscribed event returns without any `Dispatcher.dispatch` call. Consequently, the concrete dispatch implementations are no longer reachable in this no-subscriber scenario: `Dispatcher.PerThreadQueuedDispatcher.dispatch(...)` (used by the normal `EventBus` via `Dispatcher.perThreadDispatchQueue()`), `Dispatcher.LegacyAsyncDispatcher.dispatch(...)` (used by `AsyncEventBus` via `Dispatcher.legacyAsync()`), and `Dispatcher.ImmediateDispatcher.dispatch(...)` (used when an `EventBus` is configured with `Dispatcher.immediate()`). The affected call path is therefore `EventBus.post(Object)` → `EventBus.post(new DeadEvent(...))` → `Dispatcher.dispatch(...)`, with dynamic dispatch to one of those three overrides; deleting the branch eliminates it.
