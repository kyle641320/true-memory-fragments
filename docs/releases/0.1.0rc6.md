# TMF 0.1.0rc6 — Java reflex and receiver resolution

Package: `true-memory-fragments==0.1.0rc6`  
Git tag: `v0.1.0rc6`  
MCP Registry version: `0.1.0-rc6` (separate publication after public PyPI verification)

## Runtime changes since rc5

- [PR #28](https://github.com/kyle641320/true-memory-fragments/pull/28): the
  reflex now selects production Java declarations, not only Python functions.
  It checks methods, constructors, types and fields; zero eligible claims and
  unsupported/missing coverage produce explicit non-fresh warnings. Doctor
  separates registration from static language/tool coverage and rejects
  recognized legacy Java-blind hook copies. File-local declaration checks do
  not assert that every external graph dependency is fresh.
- [PR #29](https://github.com/kyle641320/true-memory-fragments/pull/29): direct
  typed receivers support bounded source-only explicit, ordinary wildcard and
  fully qualified type lookup, including cross-module source layouts. Duplicate
  definitions, shadowing and unsupported type shapes are not guessed into
  edges. Repository/delegate naming is not a special resolution rule.
- [PR #30](https://github.com/kyle641320/true-memory-fragments/pull/30): bounded
  source-defined, top-level, nongeneric inherited fields and methods resolve
  with declaration-site imports, field hiding, signature-aware overloads and
  overrides. Consulted source files and the duplicate-preserving source-symbol
  universe protect accepted and unresolved inherited lookups against staleness.
  Normal warm rebuilds affected owners, including after build-layout or Git
  trackedness changes. Java derivation version is now **v10**.

## Upgrade both engine and integration

```sh
python -m pip install 'true-memory-fragments[java]==0.1.0rc6'
tmf warm --repo /absolute/path/to/task-worktree
tmf doctor --repo /absolute/path/to/task-worktree
```

Use the intended hook interpreter/environment. The **wheel is engine-only**:
upgrading it does not register a hook or replace an existing reflex copy.
Obtain the rc6 source distribution or Git tag and update the **whole**
`integrations/reflex` directory, including `hooks/pre_tool_use.py`,
`scripts/claim_selection.py`, `scripts/state_root.py` and `scripts/local_warm.py`.
Install the matching engine's Java extra in the interpreter configured for the
hook, preserve existing host settings, and follow the
[reflex diagnostic/setup guide](../reflex-doctor.md).

Older Java derivations become version-stale; an ordinary warm rebuilds them.
A static doctor exit 0 is not proof of Claude host dispatch or complete cache
coverage. Confirm fresh allow → source mutation → stale block in a disposable
host fixture. Missing coverage still has a nonblocking, explicit warning path.
Java cross-file discovery of newly written calls remains unsupported.

## Resolution limits

This is conservative source analysis, not a full Java compiler or Spring runtime
DI resolver. External/classpath-only parents, generic ancestry substitutions,
unsupported nested/static inheritance and ambiguous interface/default-method
competition remain unresolved. Incomplete explicit ancestry can also prevent
an own-declared method from resolving because the overload pool is incomplete.
Source-only uniqueness is not compiler-classpath uniqueness.

The new inherited lookup dependency contract does not establish complete
freshness protection for all historical implicit/unqualified/super or
no-parent direct call paths. `coverage=complete` means manifest indexing is
complete, not that every semantic edge was recovered. The reported private
enterprise five-hop chain has not been replayed without its source, and the
historical Guava typed-receiver 0/7 sample has not been rescored here.
