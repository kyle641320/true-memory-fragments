# TMF 0.1.0rc5

This preview adds detection for an installed engine with an unarmed Claude Code
reflex. It builds on the rc4 package and the merged
[doctor implementation in PR #20](https://github.com/kyle641320/true-memory-fragments/pull/20).

## Changes

- `tmf doctor --repo /path/to/repo [--json]` reads Claude user, project, and
  project-local settings. Missing, disabled, incomplete, malformed, or
  unverifiable reflex registration exits 1 with the explicit warning
  `reflex NOT armed — operating as opt-in memory`.
- Exit 0 establishes supported static registration coverage, **not actual host
  execution**. JSON always reports `runtime_verified: false`. Doctor does not
  install a hook, edit settings, warm an index, or change gateway configuration.
- An offline post-install smoke covers engine-only/unarmed states before and
  after source mutation, then registration, direct fresh/stale hook behavior,
  disable/removal, and read-only diagnostics. It runs against source and an
  isolated installed wheel; it is not a new autonomous-agent A/B result.
- The source distribution includes the reflex integration and smoke assets.
  The wheel remains engine-only; copying/configuring the integration is a
  separate, explicit deployment step.
- rc4 stale-slice improvements, read-only legacy locator compatibility, and the
  legacy OpenClaw assist adapter remain included. Existing compatibility and
  installed-artifact upgrade gates remain in place.

## Install and verify

```sh
python -m pip install 'true-memory-fragments==0.1.0rc5'
tmf doctor --repo /absolute/path/to/task-repo
```

An engine-only install is expected to warn until the host hook is configured.
Follow the [reflex setup and diagnostic guide](../reflex-doctor.md), then verify
actual hook firing in the intended host. A warmed index, usage rules, and an MCP
connection are not substitutes for hook registration.

The [MCP stdio guide](../early-preview.md) pins the same `0.1.0rc5` Python package;
there is no separate MCP binary. After public PyPI verification, the Registry
manifest maps `0.1.0-rc5` to package `0.1.0rc5` and pins the Java runtime dependency
to the same version. Metadata publication is a separate workflow; the
[official rc5 record](https://registry.modelcontextprotocol.io/v0.1/servers/io.github.kyle641320%2Ftrue-memory-fragments/versions/0.1.0-rc5)
reports its live publication status.
