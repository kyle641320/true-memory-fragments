# Codex-runtime successor execution qualification (v3)

This is an **execution-layer qualification**, not a redesign, historical M10
replication, live pilot, or treatment-effect result. The existing six evidence
conditions, task, source mutation, production freshness/gate proof, fresh
control, AST scorer and compiler remain unchanged. The production engine,
README, historical results and independent raw Responses PR are untouched.

## Frozen candidate profile

The versioned profile is generated by `successor_codex_control.runtime_profile`:

- Existing host-owned OpenClaw ChatGPT/Codex subscription. No Platform API,
  credential export, second credential, or credential contents in evidence.
- Fixed OpenClaw `2026.9.2` and Codex runtime. Explicit requested
  `openai/gpt-5.6-sol`, requested native model `gpt-5.6-sol`, and requested
  effort `medium`; no inherited parent selection, OpenClaw model fallback,
  adaptive effort, or per-arm tuning. These are controls, not provider-attested
  actual model or effective effort.
- One native-function carrier, `successor_action`, over the existing seven
  action schemas. This keeps action payloads and all scientific messages
  unchanged. The additional carrier instruction is identical for every arm;
  it explains protocol submission only, never memory trust or task placement.
- The frozen request configuration, runtime version, disabled fallback, tool
  schema, permission profile and profile fingerprint must match **before each
  externally dispatched Agent turn**. The six arms use identical request
  controls, tools, budgets, task, scorer and failure policy. Native inference
  and internal retry dispatches need no successor per-dispatch reservation.
- Provider-independent pre-inference actual-model/effective-effort attestation
  is **not required**: the current runtime does not expose it. Missing provider
  attestation is an accepted observability limitation, not an admission failure.
  Request labels or a profile hash must never be copied into actual evidence.
- Reroute, effort/configuration drift, unexpected native tools, runtime failure,
  lost/corrupted observable evidence or exceeded budget stops the whole block. Abort
  acknowledgement and uncertainty are retained. No resume or replacement run.
- The native runtime must not receive the source/evaluator filesystem, shell,
  web, MCP, apps, delegation, memory tools or project documents. Source exists
  only in the controller's private workspace. Only validated local actions can
  read/change it. This is an admission requirement, not an assertion that a
  stock `--cwd` setting supplies a sandbox.

`SOURCE_ONLY` and silent withholding reuse the same scientific messages and
common carrier/tools. The warning condition still differs only by the existing
preregistered status/binding locator. Opaque schedule IDs, condition names,
scores, host paths and ledger state stay outside model-facing tools/results.

## Budgets and observability

**Equal rules and limits, not equal consumption.** No numeric limit is increased.
The execution contract uses the existing `BudgetCaps` values only at boundaries
the controller can actually enforce:

| External guardrail | Frozen limit |
| --- | --- |
| Absolute run deadline, including native runtime/retry time | 300 seconds |
| Externally dispatched Agent turns | 24 |
| Mediated actions, including `final` | 24 |
| Scientific input history plus schemas, per charged boundary / run | 120,000 / 1,200,000 UTF-8 bytes |
| Action JSON, per action / run | 16,000 / 120,000 UTF-8 bytes |
| Observable assistant output, run total | 120,000 UTF-8 bytes |
| Tool result / allowed source file | 24,000 / 240,000 UTF-8 bytes |
| Each action / each evaluator | 90 / 90 seconds |

`prepare_agent_turn` charges the full scientific history/schema material before
an external dispatch. The first unchanged action history uses that charge; it
is not charged twice. Each later action independently checks and charges the
current full scientific history before effects. Action JSON is separately
checked and charged against the unchanged output limits. Another external
dispatch charges the submitted material again, even when it is unchanged.
This is an external scientific ledger, **not** a measurement or cap on hidden
native prompt assembly or internal inference consumption.

The guard has explicit external-turn active/idle/terminal phases. A single
external turn may produce several mediated actions, internal iterations and
retries. Observing an internal inference completion does not revoke that
external turn's tool authority or consume another turn. Only the controlled
external-turn boundary ends it. Completion is terminal; a completed runtime
cannot restart. A POSIX main-thread deadline interrupts a stalled peer; nested
tool deadlines cannot reset the outer absolute deadline.

Native inference/retry counts have **no successor pre-reservation requirement
or independent count cap**. They remain under the same runtime policy and
absolute run deadline in all arms. The controller preserves available retry,
iteration, usage and runtime events; event counts are not silently promoted
into complete internal totals. Unavailable totals remain `null`/unknown. An arm
using more actual reasoning, retries, tool calls or time does not receive a
different rule or budget. Subscription usage is reported when reliable; dollar
cost is unavailable unless it can actually be computed. Cost is not a primary
outcome and consumption is exploratory telemetry only, not pilot effect evidence.

These are **not** exact native prompt-token or output-token limits. The old
required 4096 token value is preserved in the scientific material as an
unverified historical requirement, while the new profile explicitly sets the
verified provider token cap to `null`. Hidden native prompt assembly/state and
usage projection are common runtime behavior, not silently counted as measured
scientific bytes. Immutable deployment and tokenizer revisions are unavailable.

Observable output accounting uses incremental public snapshots within the same
projection identity. Equal text on distinct assistant/reasoning/preamble
projections is not deduplicated: text equality alone does not prove common
provenance. This conservative external byte ledger is not a provider token or
unique-native-output measurement.

The reporting boundary is explicit:

| Evidence class | Meaning |
| --- | --- |
| **REQUESTED AND CONTROLLED** | OpenClaw 2026.9.2, Codex runtime, `openai/gpt-5.6-sol` / native request `gpt-5.6-sol`, `medium`, disabled OpenClaw fallback, identical profile/tools/permissions/budgets. |
| **OBSERVED** | Only available runtime events with source/provenance: model/reroute, effort, configuration, runtime state, external turns, mediated actions, source reads, iterations/retries/usage when reliably reported, elapsed time and termination/cancellation. Matching runtime labels do not attest provider execution. |
| **NOT OBSERVABLE** | Independent provider pre-inference actual-model/effective-effort attestation; per-native-inference/retry pre-dispatch control; immutable deployment/tokenizer revisions; exact hidden native prompt/token accounting and unreported retry/iteration/usage totals; reliable subscription dollar conversion. Unknown facts stay absent or `null`, never filled from requests or estimated. |

Present observed model/effort/runtime/configuration mismatches still reject
admission or immediately stop the block. Reroute, tool bypass, workspace escape
and blocking runtime anomalies are equally fatal. Monitoring includes gaps
between external turns: an event cannot disappear merely because no turn is
active. Internal telemetry may arrive while idle without reopening tool
authority. Journals retain observations separately from request controls.
Notification latency is accepted: stop on observation and retain uncertainty;
do not claim zero provider tokens before a delayed notification.

The local mediator records the exact bounded source results released across
the runtime boundary. This proves source information supplied to that boundary,
not subjective model attention or that a provider subsequently consumed it.
Oversized or undurably recorded results are not marked delivered. Read/search,
edits, compile and final have the original action semantics. AST scoring and
final compilation are independent evaluator-only operations, including after
protocol failure; the model never receives the semantic score.

## Admission, durable evidence and sealing

The scientific seal is reconstructed with production freshness and compilation,
not accepted from saved PASS booleans. The joint execution seal binds that full
manifest, profile, controller/mediator/runner/host-qualifier source, ledger
policy and host inspection report. Seed `20260923` and the existing sealed
six-condition schedule are retained without re-randomization. An execution
profile/seal update must not generate or select another schedule.
An offline schedule is not six admitted live runs.

`RunAdmissionLedger` retains its unchanged default offline behavior. New
explicit Codex evidence kinds identify rehearsal versus potential live records;
they are accounting labels, not authority to execute. Codex journals require
exactly six IDs and refuse the next start after a recorded protocol failure.
Reopening is inspection-only. All six IDs are atomically admitted before any
peer construction. Per-run start is durable before workspace/runtime setup.

Runtime events are bounded, hash-chained, exclusively created and fsynced.
Their open inode and expected byte digest are checked during execution; the
run ledger pins the final event count, length, chain tail and full byte digest.
Thus a shorter, otherwise valid hash-chain prefix is not accepted as complete.
New directory entries are fsynced through their ancestor chain. Request and
action admissions are durable before dispatch/effects. A write or abort failure
cannot turn into success. Pending and never-started runs stay in ITT. Artifact
and ledger paths are never arguments to the model-facing function.

## Installed-host qualification: enforceable external boundary

The revised standard accepts the absence of provider pre-inference actual-model/
effective-effort attestation **and** the absence of per-native-inference/retry
dispatch control. Neither is a live-admission blocker. It does not upgrade
OpenClaw, declare requested labels actual identity or change scientific design.
The former per-inference reservation/cap admission requirement is superseded
only in the execution/budget contract by the external guardrails above.

Public outer-turn events can contain multiple internal iterations. Available
completion aggregates are recorded as observations, not used as retroactive
proof of pre-dispatch native control. Live qualification instead establishes
the actual external-turn/action/byte/deadline controls, private mediation and
ordered drift monitoring/cancellation. Source inspection, deterministic
regression and independent execution-only readiness review must establish
those concrete capabilities without re-auditing unchanged scientific design.

The source-only host inspector reads bounded selected package/documentation
files, not auth files or gateway config. Source hashes/anchors identify the
inspected implementation; they do not attest provider deployment. Unknown,
changed, missing or symlinked sources fail closed. A caller-written `READY`
dictionary cannot unlock live dispatch.

No arbitrary command, caller-written `READY` object, mutable bypass boolean or
fake attestation can substitute for qualification. Passing unit tests alone is
not live readiness. A genuine remaining execution blocker stops before live
admission and is reported precisely. Missing per-inference reservation or
provider attestation must not be reintroduced as replacement requirements.
No separate login, private auth-bridge import, Platform API route or OpenClaw
upgrade is authorized as a substitute.

The public plugin CLI has two disjoint modes. `--qualify` loads the same scoped
configuration and public runtime API without calling the model. `--run` accepts
one external Agent turn over an inherited private Unix socket. The source tree
is absent from the empty native carrier workspace; `successor_action` submits
validated actions to the controller. Runtime stdout/stderr are diagnostics,
never trusted control frames. The controller enforces the absolute deadline
and reaps its own host process group on termination. A cancellation request is
not reported as an acknowledged provider cancellation.

The live entry requires an independent readiness receipt bound to the clean
Git commit, joint seal, common profile and actual zero-model host qualification.
It then exclusively fsyncs a one-use latch keyed to the original schedule in
the shared Git directory before admitting the block. A different output path,
worktree or execution seal cannot replace that original block. The latch is
not released on failure. `check-live-readiness` neither claims it nor admits runs.

## Offline reproduction

With frozen Java compiler/JARs/parser dependencies and a current execution seal
bound to the **existing** scientific manifest/schedule:

```sh
python -B -W error -m unittest tests.test_m10_successor_codex_control tests.test_m10_successor_codex_host tests.test_m10_successor_codex_live tests.test_m10_successor_run_ledger
python -m bench.agent_ab.same_version_chain_v1.successor_codex_runner verify-seal --manifest /tmp/codex-execution-seal.json
python -m bench.agent_ab.same_version_chain_v1.successor_codex_runner rehearse --manifest /tmp/codex-execution-seal.json --output /tmp/codex-offline-ok
python -m bench.agent_ab.same_version_chain_v1.successor_codex_runner rehearse --manifest /tmp/codex-execution-seal.json --scenario reroute --output /tmp/codex-offline-reroute
python -m bench.agent_ab.same_version_chain_v1.successor_codex_runner check-live-readiness --manifest /tmp/codex-execution-seal.json --readiness /tmp/independent-readiness.json
```

The last command is a readiness check, not a model launch; a nonzero result
identifies a genuine remaining external execution blocker.
The authorized live entry is `run-pilot` with the sealed manifest, independent
readiness receipt, fresh output directory and a local `--host-settings` file
containing only the existing nonsecret subscription profile identifier. That
identifier is not embedded in committed source or displayed in public evidence;
the host continues to own the credentials. No arbitrary launch command is accepted.
The fixed positive peer follows the same known-answer script in every arm and
performs no model call. Fault peers cover missing/wrong requested configuration, effort drift,
configuration drift, native-tool bypass, path escape, exhausted budget and
runtime failure. These are infrastructure cases, never experimental arm data.

The authorized pilot is exactly one existing randomized block, six arms, one
live run per arm; stop after six runs or the first blocking anomaly, retain all
admitted ITT evidence, and never rerun/replace a failure. Its sole question is
whether the frozen protocol works in the real Codex Agent runtime. It cannot
establish treatment effectiveness, equivalence, warning sufficiency, or
replication/refutation of historical M10. No second block or formal effect
experiment follows automatically.

Live pilot readiness is determined by the sealed execution evidence and
independent readiness audit, not this explanatory document. If ready, the
already-authorized one-block pilot runs without another permission request;
otherwise it stops and reports the true remaining blocker. A successful pilot
does not automatically authorize or establish readiness for a formal effect
experiment. The final pilot report states that decision explicitly and never
treats either accepted runtime observability boundary as missing evidence.
