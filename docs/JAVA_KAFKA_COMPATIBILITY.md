# Java Kafka source-evidence compatibility

Schema remains `tmf.schema.v2`; existing topic and edge IDs are unchanged. This bounded phase recognizes only exact explicit Spring Kafka imports. Literal `@KafkaListener(topics="…")` declarations emit topic-mediated subscriber edges and may retain a literal `groupId`; exactly one declared listener parameter supplies declaration-only payload type metadata. Two-argument `KafkaTemplate.send("topic", payload)` calls on a source-declared `KafkaTemplate` receiver emit publisher edges; payload type is retained only for a literal or matching declared method parameter. Edge bindings use the enclosing method hash and expose an exact method anchor, so mutation/deletion follows normal freshness and reconciliation.

Coverage is partial and attributed. Dynamic topics, SpEL/placeholders, arrays/multiple topics, composed/meta annotations, overloads other than the exact two-argument shape, classpath overload resolution, serializers, partitions, keys, headers, runtime delivery, consumer-group membership/rebalancing, broker topology, external symbols, and inferred producer-consumer coupling remain unresolved or deferred. Same-simple-name decoys emit no Kafka facts.
